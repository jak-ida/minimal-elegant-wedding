# Seller guide (author only: this file is NOT in the buyer ZIP)

Everything you need to package, check and list this template. Nothing here is legal advice.

---

## 1. What ships and what does not

| In the buyer ZIP | Never in the buyer ZIP |
| --- | --- |
| `index.html`, `START-HERE.html`, `README.md`, `LICENSE.txt`, `ASSETS.md`, `TESTING.md` | `SELLER-GUIDE.md` (this file) |
| `css/`, `js/`, `assets/` (fonts, icons, **placeholder** images) | `dev-tests/` (browser test suites, scratch scripts, gzip server) |
| `start-local-server.bat`, `start-local-server.command`, `tools/serve.ps1` | `tools/make-zip.ps1`, `tools/verify-zip.ps1`, `tools/make-placeholders.py`, `tools/placeholder-images/` |
| `tools/optimise-images.py` (optional buyer helper) | `dist/`, `.git`, `node_modules`, editor folders, logs |

`tools/make-zip.ps1` builds the ZIP from an **allow-list**, so a new file in the project folder does not
ship unless you add it to the list inside the script.

## 2. Build the ZIP

```powershell
# from the project folder
powershell -ExecutionPolicy Bypass -File tools\make-zip.ps1            # safe default: placeholder images
powershell -ExecutionPolicy Bypass -File tools\make-zip.ps1 -Version 1.1
```

The script then runs `tools\verify-zip.ps1`, which extracts the finished ZIP to a temporary folder and checks:
required files present, no dev files or personal paths, forward-slash entry names (a ZIP made with
`Compress-Archive` in Windows PowerShell uses backslashes and misbehaves on macOS and Linux; the script writes the
ZIP itself to avoid this), every referenced file exists, no unused files, demo photos absent (by SHA-256 hash), the
font licence travels with the fonts, demo RSVP mode is the shipped setting, and the documents do not claim backend
features. It exits non-zero on any failure.

Optional real load test of the finished ZIP (needs Node.js and Puppeteer, see `dev-tests/README.md`):

```powershell
node dev-tests/zip-smoke.js dist\wedding-template-v1.0.zip
```

It extracts the ZIP, starts the **shipped** `tools/serve.ps1` server on the extracted copy, loads the page in Chrome at phone and desktop
widths and checks for console errors, failed requests, broken images, missing fonts, empty content slots and
horizontal overflow.

## 3. Before you sell: things only you can do

1. **Licence text.** Fill in `[Your Name or Studio Name]`, `[your-email@your-domain.com]` and `[Year]` in
   `LICENSE.txt`, and have the wording reviewed by someone qualified in your country. `make-zip.ps1` prints a
   reminder while those placeholders remain.
2. **Attribution line.** Replace `Your Studio Name` in `js/config.js` (`footer.attributionText`) and decide which
   licence tier allows removing it.
3. **Images.** Read section 4 below. The default ZIP contains no photographs.
4. **Live demo.** Deploy the project folder (with the demo photos, if you are allowed to show them) as your
   shop's preview. A demo is not the product: it can use images the buyer does not receive.
5. **Test the exact ZIP** you will upload: unzip it somewhere fresh and follow `START-HERE.html` yourself on a
   clean machine if you can (Windows and Mac).
6. **Support promise.** Decide what you will answer (installation, bugs) and what you will not (hosting, RSVP
   service accounts, custom design).
7. **Do not describe the template as "production-ready for data collection".** It becomes that only once the
   buyer connects, tests and secures their own RSVP service.

## 4. Asset legality: what can and cannot be redistributed

Full detail is in `ASSETS.md`. Summary of the status **at the time this guide was written**:

| Asset | Status | Action |
| --- | --- | --- |
| Cormorant Garamond and DM Sans (`assets/fonts/*.woff2`) | **Can be redistributed.** SIL OFL 1.1. Copyright lines and the absence of a Reserved Font Name were checked against the upstream `OFL.txt` files (Cormorant: CatharsisFonts/Cormorant; DM Sans: google/fonts `ofl/dmsans`). | Keep `assets/fonts/OFL.txt` in every copy. Never sell the font files by themselves. |
| `assets/fonts/OFL.txt` | Required licence file. | Do not remove. |
| Icons, ornament, favicon (inline SVG and `favicon.svg`) | Drawn for this template. | Covered by your licence. |
| Placeholder images (`tools/placeholder-images/`) | Generated by `tools/make-placeholders.py` from plain colour, a line pictogram and text. No photograph, no person, no third-party material. | These ship by default. |
| Sample wording in `config.js` / `index.html` (names "Amara and Daniel", venue "Willowbrook Gardens", story, FAQ) | Written for this template and fictional. | Check that no real venue of that name makes it misleading in your market. |
| **Demo photographs** (`assets/images/*.webp`, `og-image.jpg` in the project folder) | **Cannot be confirmed as redistributable.** They are AI-generated. Whether you may include them in a paid download depends on the terms of the generator used and on the law where you sell; in some countries purely AI-generated images may not be protected by copyright, so you could not stop buyers copying them either. This project cannot determine that for you. They also depict fictional people. | **Excluded from the ZIP by default.** Use them only for your own live demo, unless you have read the generator's terms and are satisfied they allow commercial redistribution. Then build with `-IncludeDemoPhotos`. |
| Any stock photo you may add later | Many free-stock licences forbid redistribution inside a paid template. | Read each licence, or do not include it. |
| Google Maps / example.com / Instagram links in the sample config | Plain links to third-party sites. No content is copied. `example.com` is reserved for documentation. | Buyers replace them. |
| Third-party code | None. No libraries, CDNs or trackers. | `dev-tests/` uses Puppeteer, axe-core and Lighthouse but none of that is shipped. |

If you decide to ship `-IncludeDemoPhotos`, say in the listing that the photos are AI-generated samples, and
say whether the buyer may use them on their own wedding site (the safest answer is that they should not).

## 5. Suggested listing text (honest)

> A romantic, editorial one-page wedding website in plain HTML, CSS and JavaScript: no framework, no build step, no
> subscriptions. Edit one file to change names, date, story, schedule, FAQs, gallery and colours. Includes a live
> countdown, an accessible photo viewer, a FAQ accordion, travel and gift sections, and an RSVP form with a
> documented adapter for **your own** form service. You can preview it on your computer without installing
> anything (a Windows launcher is included), then upload the folder to any static host.
>
> **Please note:** this is a static website. RSVPs are **not stored or sent** until you connect a form service
> (instructions included); until then the form runs in a clearly labelled demo mode. No photographs are
> included: the pictures are grey placeholders for your own photos. Tested in Chrome with automated checks; not
> tested in Safari or Firefox or on real phones, and not checked with a screen reader.

## 6. Running the QA suites

Needs Node.js, Chrome, `puppeteer-core`, `axe-core` and `lighthouse` (see `dev-tests/README.md`). With the
template served on `http://127.0.0.1:8123/`:

| Script | Covers |
| --- | --- |
| `dev-tests/functional.js` | Original 92 checks: page health, countdown, menu, banner, FAQ, lightbox, RSVP demo and simulated production, motion, responsive. |
| `dev-tests/qa-a.js` | Assets, links, deep links, semantics, axe scans in 10 states, text over photos, 29-width live-resize sweep, 200% font and text spacing. |
| `dev-tests/qa-b.js` | RSVP states, simulated endpoint, countdown behaviour (offsets, time zones, clock jumps, invalid dates), gallery and touch, keyboard walks, reduced motion, print. |
| `dev-tests/qa-c.js` | Missing files, restricted browser features, hostile config, external links, print, forced colours, dark scheme, initial load. |
| `dev-tests/zip-smoke.js` | Load test of the built ZIP. |

Recorded results are in `dev-tests/RESULTS.md`.
