Start here

This guide takes you from the downloaded ZIP to a wedding website on your own computer, then to the internet. You do not need to install a framework, a programme or a package manager, and you do not need to be a programmer. You need a web browser and a plain text editor.

Jump to: 1 Unzip 2 Preview 3 Your details 4 Photos 5 Page title and sharing 6 RSVP 7 Put it online 8 Final check Troubleshooting What it does not do

Please read this one thing first. This is a static website: a folder of files. It has no server behind it. That means the RSVP form does not save or send anything until you connect your own form service (Step 6). Until then it runs in a clearly labelled demo mode. Do not send the link to your guests before you have done Step 6 and tested it.

1 Unzip the download

  • Windows: right-click the ZIP, choose Extract All…, then Extract. Do not open files from inside the ZIP window; they will not work there.
  • Mac: double-click the ZIP.

You get a folder called wedding-template. Move it somewhere easy to find, such as your Documents folder. The important things inside it:

File or folderWhat it is
index.htmlThe website itself. Open this in a browser.
js/config.jsThe file you edit. Names, date, story, schedule, FAQ, links, colours.
assets/images/The pictures. They are grey placeholders; you replace them with your own photographs.
start-local-server.bat / .commandDouble-click to preview the site on your computer (Windows / Mac).
README.mdThe full reference guide.
LICENSE.txt, ASSETS.mdWhat you may do with the template, and where each font and image comes from.

2 Preview the website on your computer

Pick one of these. Option A is quickest; Option B shows the site exactly as it will look online.

Option A: just double-click index.html

It opens in your browser. This was checked in Google Chrome. If anything looks wrong in another browser (fonts missing, a blank page), use Option B instead. Chrome may print a couple of harmless messages about fonts in its developer console when you open the file this way; they go away with Option B.

Option B (recommended): start the built-in preview server

This runs a tiny web server on your own computer only. Nobody else can see it, and nothing is uploaded.

  • Windows: double-click start-local-server.bat. A black window opens and your browser shows the site at http://localhost:8000. If Python 3 is installed it is used; if not, a small built-in Windows script is used, so nothing has to be installed. If Windows says “Windows protected your PC”, that is its normal warning for downloaded scripts: choose More info, then Run anyway (or use Option C or D, which avoid this).
  • Mac: the first time only, open Terminal, type chmod +x (with a space after it), drag start-local-server.command into the Terminal window, press Return. After that you can double-click the file. If macOS blocks it, right-click the file, choose Open, then Open again.
  • Linux: in a terminal inside the folder, run sh start-local-server.command.

To stop the server, close the black window (or press Ctrl+C). After you edit and save a file, just refresh the browser tab.

Option C: Visual Studio Code

Open the folder in VS Code, install the free “Live Server” extension, right-click index.html and choose Open with Live Server.

Option D: a command in a terminal

Open a terminal inside the wedding-template folder and run one of these (you only need one):

python -m http.server 8000      # needs Python 3; then open http://localhost:8000
npx serve .                     # needs Node.js; then open the address it prints

3 Put in your own details

Open js/config.js in a plain text editor (Notepad, TextEdit set to plain text, or VS Code). Do not use Word or Google Docs: they change quote marks and break the file. Everything is in numbered sections with sample values. Change the words between the quote marks, save, refresh the browser.

Do these first (about ten minutes):

  1. couple: both names.
  2. wedding.dateTime: your date and time, e.g. "2027-06-19T14:30:00". Add an offset such as +02:00 if guests live in several time zones (details in README.md).
  3. details: venue, address and the “Get Directions” link (open your venue in a map service, press Share, paste the link).
  4. schedule, story, faq, introductions: replace the sample text or delete what you do not need.
  5. faq.contact: a real e-mail address or phone number.
  6. gifts and travel: real links, or set a link to "" to hide it.

Rules that keep the file working

  • Keep the straight quote marks " around text, and keep the commas at the end of lines. Most problems come from a missing quote or comma.
  • If your text contains a quote mark, write it as \". Example: "She said \"yes\"".
  • \n inside a heading makes a line break. Words wrapped in *asterisks* become the italic gold accent.
  • Text is shown exactly as typed. Web-page code (HTML) is shown as text, on purpose.
  • To remove an item (a schedule row, an FAQ question), delete everything from its { to its } and the comma after it.
  • If you save a mistake, the page may go blank. Open the browser console (F12, then Console) and it names the problem and the line. Undo your last change and try again.

4 Replace the placeholder pictures

The pictures in assets/images/ are grey placeholders that show you the size and shape each slot needs. Each one has the size printed on it. The easiest way: prepare your photo to the same shape, export it as WebP or JPEG, and save it over the placeholder with the same file name. No code changes needed. README.md has a table of every slot with recommended sizes.

  • Photos make the page slow if they are huge. Aim for WebP at quality 75–82 and the widths listed in the table. Free tool: squoosh.app.
  • Update the description (alt) of every photo in config.js. It is read aloud to blind visitors and shown if a picture fails to load. The placeholder text says “Placeholder image” so you can search for it and be sure none is left.
  • Only use photographs you own or have permission to use, and ask people in them if you are unsure.

5 Page title and link previews (one edit in index.html)

Open index.html and look at the top of the file. Lines marked REPLACE control the browser-tab title, the Google description and the picture and text shown when your link is shared in a chat app. Update them with your names and, once you know it, your real web address. The sharing picture is assets/images/og-image.jpg (1200 × 630). Replace the favicon (assets/icons/favicon.svg) with your initials if you like.

6 RSVP: what it does and what you must add

Out of the box, nothing is saved or sent. The form checks the answers and shows a screen that says plainly it is a demonstration. A website made of static files cannot store guest replies by itself, and this template does not include a database, a server or an e-mail service.

To collect real replies you connect a service you choose and control, in config.js under rsvp:

  1. Create a form with a form-handling service (examples: Formspree, Getform, Basin, FormSubmit) or use your own serverless function. Copy the https://… address it gives you.
  2. Set mode: "production" and paste the address into endpoint.
  3. Upload the site (Step 7), submit a real test RSVP from the live site and confirm it arrives. Test an accept, a decline, and a name with an accent or apostrophe.

Things to know:

  • Never put passwords or secret keys in any file of this website; everyone can read them.
  • The connection was checked here against a simulated service only, not against any real company’s service. That is why Step 6.3 matters.
  • If the endpoint is empty or not https, the form falls back to demo mode instead of pretending to send.
  • You are responsible for how you store and protect guests’ names and e-mails, and for any privacy statement your local law requires. There is an editable one-line privacy note under the form.
  • There is no guest list, invitation code, reminder e-mail or confirmation e-mail. The service you connect may offer some of these.

7 Put the website online

Upload the contents of the folder (keep the folders inside it exactly as they are) to any service that hosts static files. Examples (all have free or low-cost plans; check their current terms):

ServiceHow
NetlifyDrag the folder onto the “Netlify Drop” page.
Cloudflare PagesCreate a project and choose direct upload.
GitHub PagesPut the files in a repository and switch on Pages in its settings.
Ordinary web hostingUpload everything into public_html (or www) with the file manager or FTP.

Afterwards: put your real address into the canonical, og:url, og:image and twitter:image lines in index.html (the image address must start with https://), make sure the address starts with https://, and re-upload. You do not upload start-local-server.*, README.md, ASSETS.md, TESTING.md, LICENSE.txt or this file; they are harmless if you do, but not needed. Keep assets/fonts/OFL.txt with the fonts.

8 Final check before you send the link

  • Search config.js for example.com, Amara, Daniel, Willowbrook, Placeholder image and Your Studio Name. None should remain, unless you keep the template credit (see LICENSE.txt).
  • Open the live site on a real phone and on a computer. Scroll everything, open the menu and a photo, and send a test RSVP.
  • Ask someone else to proofread the dates, times and address.
  • TESTING.md has a longer checklist, including keyboard and screen-reader checks.

Troubleshooting

ProblemWhat to try
The page is blank or shows only a noticePress F12, open Console, read the red message. It is nearly always a missing quote mark or comma in js/config.js in the place you edited last. Undo that edit. Also check that JavaScript is not switched off in the browser.
My changes do not appearDid you save the file? Hold Shift and click refresh. Make sure you edited the copy of the folder that you are previewing.
The countdown shows nothingThe date is not a real date (for example 30 February or month 13). The console says so. Use the format "2027-06-19T14:30:00".
Fonts look plain when I double-click index.htmlUse Option B (the preview server) or upload the site. Browsers other than Chrome can be stricter about files opened directly from disk.
start-local-server.bat closes immediatelyAdministrator rights are not needed. Try Option C or D instead. If port 8000 is already in use, the built-in Windows server picks the next free port and prints the address in its window; the Python version needs you to close the other program first.
Windows warns about the .bat fileThat is normal for downloaded scripts. Choose More info, Run anyway, or use Option C or D.
A photo looks stretched or blurryUse the same shape and the recommended width for that slot (table in README.md), and set the real width and height in config.js if you changed file names.
RSVP says “demo” on the live sitersvp.mode is still "demo", or the endpoint is empty or not https. See Step 6.

What this template does not do

  • It does not store RSVPs, send e-mails, manage a guest list, take payments or run any server code. Those need a service you connect.
  • The words on the page are written by JavaScript from config.js. A visitor who has JavaScript switched off sees the design and pictures but not the wording.
  • It is in English. You can translate the text in config.js and some labels in index.html, but there is no language switcher and right-to-left languages are not styled.
  • It has been checked with automated tests in Chrome and with accessibility scanners. It has not been tested in Safari or Firefox, on real phones, with a real screen reader, or against a live RSVP service. Please do your own checks (TESTING.md).
